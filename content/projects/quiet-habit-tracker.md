## 개요

기존 습관 앱들은 지하철에서 열면 로딩 스피너만 돌았습니다. 하루에 한 번 체크하는 앱이 네트워크에 의존한다는 게 납득이 되지 않아서, "오프라인이 정상 상태이고 온라인이 보너스"인 구조로 다시 만들었습니다.

모든 쓰기는 먼저 IndexedDB에 들어가고 UI는 즉시 반응합니다. 동기화는 백그라운드에서 일어나며, 실패해도 사용자는 알 필요가 없습니다.

## 주요 기능

- **로컬 우선 쓰기** — 사용자 동작은 예외 없이 로컬에 먼저 커밋됩니다. 낙관적 업데이트가 아니라 애초에 로컬이 원본입니다.
- **CRDT 기반 병합** — 기기 두 대에서 같은 날짜를 다르게 기록해도 손실 없이 합쳐집니다. 습관 체크는 last-write-wins 레지스터, 메모는 텍스트 시퀀스로 모델링했습니다.
- **Service Worker 라우팅** — 앱 셸은 cache-first, 동기화 요청은 network-only에 재시도 큐를 붙였습니다.
- **스크린리더 우선 설계** — 히트맵 그리드를 시각 요소가 아니라 표로 구성하고, 각 셀에 날짜와 상태를 읽어주는 접근 가능한 라벨을 붙였습니다. NVDA와 VoiceOver로 실제 검증했습니다.
- **로컬 내보내기** — 계정 없이도 전체 데이터를 JSON으로 내보내고 되돌릴 수 있습니다. 계정은 선택 사항입니다.

## 배운 것

"오프라인 지원"을 나중에 얹으려 하면 데이터 흐름을 전부 다시 써야 합니다. 첫 버전에서 fetch 결과를 곧바로 렌더링하는 코드를 짰다가, 동기화를 붙이는 단계에서 컴포넌트 대부분을 버렸습니다. 두 번째 시도에서는 IndexedDB를 유일한 읽기 소스로 고정하고 네트워크는 그저 로컬을 갱신하는 파이프로만 취급했습니다. 그러자 온라인/오프라인 분기가 코드에서 사라졌습니다.

CRDT는 이론보다 시계 문제가 어려웠습니다. 기기 시계를 신뢰하면 과거로 설정된 기기가 미래의 기록을 덮어씁니다. 하이브리드 논리 시계를 도입해 물리 시간과 논리 카운터를 함께 보도록 고쳤습니다.

접근성 작업은 결과적으로 코드를 단순하게 만들었습니다. 히트맵을 `<table>`로 다시 쓰면서 직접 관리하던 좌표 계산이 통째로 사라졌습니다.
