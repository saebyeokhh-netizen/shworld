## 왜 Supabase 가 아니라 D1 인가

기획서 원안은 Supabase 였다. 인증과 DB 를 다 주니까 작업량이 훨씬 적다. 그런데 무료 플랜에 걸리는 조건이 있었다 — **1주일 미사용 시 프로젝트가 자동 정지된다.**

며칠 쉬었다가 친구에게 링크를 보냈는데 로그인이 안 되는 상황이 실제로 생긴다. 게다가 정지는 조용히 일어나서, 누가 알려주기 전까지는 모른다. 취미로 만드는 게임에서 이건 꽤 나쁜 실패 방식이다.

D1 은 정지 개념이 없고, 무료 한도(5GB, 하루 500만 행 읽기)도 우리 규모에서는 사실상 무제한이다. 대신 OAuth 흐름을 직접 구현해야 한다. 그 일은 내가 하면 되고, 사용자가 해야 하는 일(구글·카카오 콘솔에서 키 발급)은 어느 쪽을 골라도 똑같다.

## 로그인 구조

표준 OAuth 2.0 인가 코드 방식이다.

```
앱 → /auth/google/start → 구글 로그인 → /auth/google/callback → 앱으로 복귀(#token=...)
```

**쿠키를 쓰지 않았다.** 게임 화면(`schoolking.pages.dev`)과 서버(`workers.dev`)는 도메인이 다르다. 세션을 쿠키로 들고 다니면 서드파티 쿠키가 되는데, 사파리를 비롯한 여러 브라우저가 이를 막는다. 그래서 로그인 결과를 **서명된 토큰**으로 만들어 앱에 넘기고, 앱은 요청마다 `Authorization: Bearer` 로 보낸다. 도메인 정책에 휘둘리지 않는다.

토큰은 주소창의 **fragment(`#`)** 로 넘긴다. 쿼리스트링으로 넘기면 서버 로그와 리퍼러에 남을 수 있는데, fragment 는 서버로 전송되지 않는다. 앱은 받자마자 저장하고 주소에서 지운다 — 남겨두면 주소를 공유하는 순간 계정도 함께 넘어간다.

CSRF 는 `state` 로 막는다. 돌아갈 주소를 state 에 담아 서명해두고 콜백에서 확인하므로, 서버가 세션을 따로 보관하지 않아도 위조를 걸러낸다. 돌아갈 주소는 허용 목록과 대조한다 — 아무 데나 보내주면 열린 리다이렉트 취약점이 된다.

## 전적

`RecordStore` 라는 인터페이스를 두고 구현을 두 벌 만들었다.

| 상태 | 저장 위치 |
|---|---|
| 로그인 전 | 이 기기 (`localStorage`) |
| 로그인 후 | 서버 (D1) |

화면은 어느 쪽인지 모른다. **로그인 없이도 전적이 쌓이게 한 이유**는, 계정을 만들기 전에 먼저 해보는 사람이 대부분이기 때문이다. 처음 온 사람에게 로그인부터 요구하면 한 판 해보지도 않고 떠난다. 로그인 화면에도 "로그인 없이 둘러보기" 를 넣었다.

기기에 쌓인 기록이 로그인 시 서버로 옮겨가지는 않는다. 옮기려면 "이 기기의 기록을 계정에 합칠까요?" 같은 확인이 필요하고, 그건 계정 기능이 자리잡은 뒤에 할 일이다.

**끝난 판에서 기록 한 줄을 만드는 계산은 순수 함수로 떼어냈다**(`buildMatchRecord`). 화면의 `useEffect` 안에 두면 "등수를 어떻게 세는가" 가 UI 코드에 숨는다. 나중에 서버가 직접 기록하게 될 때도 그대로 옮긴다.

## 전적 화면

요약 카드(승률을 크게, 그 아래 총 판수·1등 횟수·평균·최고 점수) + 최근 기록 목록. 1등은 골드 왕관, 점수는 부호와 색으로 구분한다. 날짜는 "오늘 14:32 / 어제 / 8월 18일" 처럼 사람이 읽는 방식으로 적는다.

기록이 없을 때는 "아직 기록이 없어요. 한 판 하고 오세요" 와 매칭으로 가는 버튼을 보여준다. 읽는 중과 기록 없음을 구분해서 빈 상태가 깜빡이지 않게 했다.

## 검증

- 단위 테스트 **30개 추가**(localRecords 14, summarize 8, buildMatchRecord 8) → 전체 **197개 통과**
- 배포된 서버: `/api/me` 가 비로그인에 `{"user":null}`, `/auth/google/start` 는 키가 없어 503 (설정 전이라 정상)
- 브라우저: 전적 빈 상태 → 기록 3건 표시(승률 33%, 평균 133점) → 홈 타일에서 이동 → 로그인 버튼이 서버의 `/auth/{provider}/start` 로 이동하는 것까지 확인

## 남은 것 — 키 발급

구글·카카오 콘솔에서 OAuth 앱을 만들어야 로그인이 실제로 동작한다. 둘 다 무료다. 발급받은 값은 `wrangler secret put` 으로 서버에 넣는다(저장소에는 들어가지 않는다).

세션 서명 키는 무작위로 만들어 이미 넣어뒀다.
