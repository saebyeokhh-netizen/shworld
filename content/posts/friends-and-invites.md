## 설정

게임(소리·진동) / 도움말 / 계정 / 정보 네 묶음으로 갈랐다. 항목이 몇 개 안 되지만 성격이 다른 것들이 한 줄로 이어지면 **계정 탈퇴 같은 위험한 항목을 실수로 누르기 쉽다.**

**소리·진동은 값만 저장한다.** 아직 효과음을 내는 코드가 없다. 나중에 재생 코드가 이 값을 읽어 쓰기로 하고, 그 사실을 코드 주석에 남겼다. 화면에는 "이 기기에만 저장돼요" 라고 적었다 — 계정을 옮겨도 따라오지 않는다는 뜻이다.

**계정 탈퇴는 같은 화면 안에서 한 번 더 묻는다.** `window.confirm` 을 쓰지 않은 이유가 둘이다. 브라우저 기본 대화상자는 화면 톤과 어긋나고, 모바일 웹뷰에서 아예 막히는 경우가 있어 확인 없이 넘어갈 위험이 있다. 확인 문구가 그 항목 자리를 그대로 대체해서, 무엇을 지우는지 보면서 누르게 된다.

크레딧(`Made by SH` / `Thanks to Nimo`)은 PRD 5-10 이 명시한 항목이라 화면 맨 아래에 넣었다.

## 친구

**친구 코드로 맺는다.** 닉네임 검색을 열면 이름만 아는 사람이 찾아올 수 있고 동명이인도 구분되지 않는다. 코드를 알려준다는 행위 자체가 "추가해도 좋다" 는 동의라서 수락 절차 없이도 자연스럽다.

코드는 6자이고 `0/O`, `1/I` 처럼 눈으로 헷갈리는 글자를 뺐다. 코드는 결국 사람이 불러주고 받아 적는 값이다. 입력할 때도 대소문자·공백·하이픈을 신경 쓰지 않게 다듬어서 보낸다 — `3ds-cmp` 로 쳐도 `3DSCMP` 로 들어간다.

**관계는 양방향으로 두 줄을 넣는다.** 한 줄만 저장하고 조회할 때 양쪽 컬럼을 뒤지면 질의가 복잡해지고, 무엇보다 삭제할 때 "누가 지웠는가" 에 따라 한쪽에만 남는 상태가 생긴다. 두 줄이면 넣을 때도 지울 때도 대칭이라 어긋날 여지가 없다.

**친구 코드는 처음 필요할 때 만든다.** 가입 시점에 발급하지 않는 이유는, 친구 화면에 한 번도 안 들어간 사람에게까지 코드를 쥐여줄 이유가 없어서다. 이미 가입한 계정도 자연스럽게 채워진다.

지금은 푸시 알림이 없어서 "친구를 방으로 초대" 가 아니라 **"방 만들고 코드 알려주기"** 다. 그 사실을 화면에 적어뒀다 — 초대 버튼을 눌렀는데 상대에게 아무 일도 안 일어나면 고장으로 보인다.

## 계정 탈퇴가 지우는 것

계정만 지우면 남의 친구 목록에 이름 없는 자리가 남고, 전적은 주인 없는 기록이 된다. 그래서 사용자·전적·친구 관계를 한 번에 지운다.

## 헤맨 곳 — 죽지 않은 개발 서버

친구 API 를 로컬에서 검증하는데 계속 401 이 나왔다. 서명 키도 넣었고 DB 에 사용자도 있는데 인증이 안 됐다.

원인은 코드가 아니라 **포트를 먼저 잡은 예전 개발 서버**였다. `wrangler dev` 를 여러 번 다시 띄우는 사이 예전 프로세스가 살아남아 8787 을 계속 물고 있었고, 새로 띄운 쪽은 "Ready" 만 찍고 실제 요청은 받지 못했다. 예전 프로세스에는 서명 키가 없었으니 계속 401 이었던 것이다.

진단용 경로를 하나 만들어 `hasSecret` 을 찍어보고서야 알았다 — 시작 로그에는 키가 보이는데 응답하는 쪽에는 없다는 모순이 단서였다. 프로세스를 전부 정리하고 하나만 띄우니 바로 통과했다.

## 검증

`server/test/` 방식과 같이, 로컬 서버에 테스트 계정 둘을 넣고 실제 HTTP 로 확인했다.

| 확인 | 결과 |
|---|---|
| 코드 발급 — 6자, 서로 다름, 다시 불러도 같은 코드 | OK |
| 없는 코드 / 짧은 코드 / 내 코드 | 각각 알맞은 안내 |
| 소문자·하이픈 섞인 코드로 추가 | OK |
| 중복 추가 차단 | "이미 친구예요" |
| 양쪽 목록에 모두 보임 | OK |
| 한쪽이 삭제하면 양쪽에서 사라짐 | OK |
| 위조 토큰 | 401 |

마지막 항목은 처음에 **500** 이 나왔다. 아무렇게나 만든 토큰이 오면 base64 디코딩에서 예외가 터졌기 때문인데, 잘못된 토큰의 올바른 답은 "인증 안 됨" 이지 "서버 오류" 가 아니다. 검증 전체를 try 로 감쌌다.

브라우저에서도 확인했다 — 설정 화면의 크레딧 표시와 토글 저장, 친구 화면의 코드 표시와 실제 친구 추가(목록에 상대가 나타남)까지. 테스트 218개 통과.

## 남은 것

**출석체크는 미뤘다.** 코인 경제가 아직 가짜 값이라, 보상을 주는 화면을 만들면 그 순간부터 앞뒤가 안 맞는다. 상점 결제와 함께 묶어서 하는 게 맞다.

## 왜 이걸 했나

제보가 두 가지였다.

> "내가 카카오톡으로 초대한 링크 누르면, 내가 아니라 E 님이 떠서 막아놨던 건데,
> 이제 링크 눌렀을 때 어플로 다시 넘어가서 A 님(나)로 있게 되면 게스트 모드도 상관없어."

> "누가 내 코드 받아서 친구추가하면 친구요청 / 받은 목록 같은 게 있어야 할 거 같아.
> 수락을 누를 수 있어야지."

첫 번째는 **로그인 필수 여부가 본질이 아니었다는 뜻이다.** 문제는 "링크를 누르면 내가 딴
사람이 된다" 였고, 로그인 강제는 그걸 막으려던 우회였다. 원인을 없애면 게스트 모드로 둬도
된다.

## 1. 인앱 브라우저에서 사람이 바뀌던 이유

카카오톡 안의 브라우저는 **저장소가 따로**다. 평소 쓰던 브라우저나 설치한 앱에 들어 있는
내 식별자(`clientId`)와 닉네임이 거기엔 없다. 그래서 링크를 누르면 처음 온 사람으로 취급되어
새 임시 닉네임(E 님94 같은)이 붙는다. 자기가 만든 방에 자기가 들어갔는데 딴사람이 되는
이유가 이것이었다.

고친 방향은 "인앱 브라우저에서 잘 되게" 가 아니라 **거기 머물지 않게** 하는 것이다.

- 앱이 뜨기 전(`main.tsx`)에 인앱 브라우저를 감지하면 곧바로 바깥 브라우저로 넘긴다.
  카카오톡은 `kakaotalk://web/openExternal`, 그 밖의 안드로이드 앱은 `intent://` 로 크롬을
  지목한다. **보고 있던 주소 그대로** 넘기므로 나가자마자 그 방이다.
- **한 번만 시도한다**(`sessionStorage`). 일부러 되돌아온 사람을 또 튕겨내면 빠져나갈 수가
  없다. 자동 전환이 막힌 경우에는 화면의 안내 배너가 눌러서 나가는 길을 준다.

넘어간 브라우저에는 평소 쓰던 저장소가 그대로 있으므로, 로그인해 뒀다면 그 계정으로,
게스트라도 늘 쓰던 그 이름으로 들어간다.

## 2. 친구 요청 — 코드는 요청까지만 만든다

지금까지는 코드를 넣는 즉시 양쪽이 친구가 됐다. 코드를 알려준 것 자체가 동의라고 봤기
때문인데, **코드는 한 번 알려지면 계속 남는다.** 단톡방에 올린 코드를 나중에 본 사람,
코드를 전달받은 제3자까지 그대로 친구 목록에 들어온다.

이제 코드는 **요청**까지만 만든다.

- `friend_requests` 표 한 줄. 친구 관계는 대칭이라 두 줄로 저장하지만, 요청은 방향이 곧
  의미라 한 줄이다. 수락하면 이 줄이 사라지고 `friends` 에 두 줄이 생긴다.
- 화면에 **받은 요청**(수락 / 거절)과 **보낸 요청**(취소)이 따로 뜬다. 보낸 것도 보여주는
  이유는 "코드를 넣었는데 왜 친구 목록에 없지" 를 설명하기 위해서다 — 기다리는 중이라는 게
  보이면 같은 코드를 몇 번씩 다시 넣지 않는다.
- **예외 하나:** 상대가 이미 내게 요청을 보내둔 상태에서 내가 그 사람 코드를 넣으면 그
  자리에서 친구가 된다. 서로 코드를 주고받은 사이에게 수락을 한 번 더 시킬 이유가 없다.
- 응답 코드로 두 갈래를 구분한다 — 201(그 자리에서 친구), 202(요청 접수). 화면 문구도
  다르게 나간다.

탈퇴하면 그 사람이 얽힌 요청도 함께 지운다. 남겨두면 이름 없는 요청이 남는다.

## 확인한 것

- 요청 목록 → 수락 → 친구 목록으로 옮겨가고 요청 줄이 사라지는 흐름을 브라우저로 확인했다.
- 서버·DB 는 프로덕션에 적용했다(`0005_friend_requests.sql`, 워커 배포).
- 테스트 245개 통과.

## 곁다리로 고친 것

친구 화면의 "아직 초대 알림이 없어서 코드를 직접 알려줘야 해요" 문구가 낡아 있었다.
접속 중인 친구를 부르면 상대 화면에 입장 확인 팝업이 뜨는 기능이 이미 들어와 있다.
