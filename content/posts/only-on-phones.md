## 어떻게 봤나

브라우저를 실제 기기 폭으로 띄워 **모든 화면**을 훑는 검사를 만들었다
(`scratchpad/sweep.mjs`). 눈으로 보는 대신 두 가지를 재게 했다.

- **가로로 넘친 요소** — 화면 오른쪽 밖으로 나간 것. 문서 가로 스크롤을 막아둔 앱이라
  넘친 만큼 **그냥 잘려 나간다.**
- **세로로 잘린 요소** — 스스로 스크롤하지 않는 칸 안에서 화면 아래로 밀려난 것.
  스크롤되는 칸(`.screen-body`) 안은 제외했다 — 거기는 내리면 보인다.

폭은 9가지: 320(구형 아이폰SE) / 360(보급형) / 375 / 390 / 393 / 412 / 430(프로맥스) /
280(폴더블 커버). 화면은 홈·로비 셋·방·전적·친구·설정·게임설명·개인정보·상점 둘·튜토리얼,
그리고 실제로 판을 열어 **게임 화면**(예측 팝업 / 카드 화면)까지.

## 찾은 것

**홈 화면 머리말이 모든 폭에서 넘치고 있었다.** 제보한 기종만의 문제가 아니었다.

| 폭 | 넘친 양 |
|---|---|
| 320 | **+115px** |
| 360 | +83px |
| 390 | +53px |
| 412 | +31px |
| 430(가장 큰 폰) | +13px |

아바타·이름·트로피·코인·아이콘 셋이 한 줄에 들어가는데, 그 합이 **가장 큰 폰에서도**
화면보다 넓었다. 오른쪽 끝의 설정 아이콘부터 잘려 나간 이유다.

게임 화면은 320px 에서 머리말 아이콘이 2px 잘렸다.

## 어떻게 고쳤나

**줄여서 우겨넣지 않았다.** 320px 에서는 아무리 줄여도 모자란다 — 필요한 폭이 화면보다
100px 넘게 크다. 대신 **오른쪽 덩어리가 통째로 아랫줄로 내려가게** 했다.

- 트로피·코인과 아이콘을 한 덩어리로 묶었다. 따로 두면 아이콘만 떨어져 트로피 옆이 휑해진다.
- 이름은 자리가 모자라면 말줄임된다(`min-width: 0` 이 있어야 실제로 줄어든다).
- 360px 이하에서는 아이콘과 뱃지를 한 단계씩 줄인다.
- 게임 화면은 340px 이하에서 좌우 여백을 한 단계 줄였다 — 2px 때문에 요소를 빼는 건 과하다.

두 줄이 되어도 잘리는 것보다 낫다. 실제로는 대부분의 폰에서 두 줄이 되는데, 아랫줄이
오른쪽 정렬이라 균형이 무너지지 않는다.

## 결과

9가지 폭 × 13화면 + 게임 화면 두 상태 — **전부 통과.** 가로로 넘치는 것도, 세로로 잘리는
것도 없다.

검사 스크립트는 화면을 크게 손볼 때마다 다시 돌리면 된다. 눈으로 훑는 것보다 정확하고,
"어느 기종에서 몇 px" 이 바로 나온다.

## 1. "AI와 연습하기" 가 곧바로 판을 열던 것

매칭에서 상대를 못 찾았을 때 뜨는 팝업의 그 버튼이, 매칭에서 고른 인원 그룹과 턴 시간으로
**곧장 카드를 깔았다.** 몇 명과 하는지 정할 기회도 없이 판이 시작되니 당황스럽다.

이제 **연습 설정 화면**으로 보낸다. 연습은 규칙을 익히거나 시험해 보려고 하는 것이라,
조건을 고르는 화면을 한 번 거치는 편이 맞다. 방에서는 먼저 빠져나간다 — 남아 있으면 남의
명단에 유령으로 남는다.

## 2. 폰의 강제 다크 모드 — 감지할 수 있나?

**감지할 수 없다.** 그 일은 브라우저가 페이지를 다 그린 **뒤에** 일어난다. 우리가 색을
읽어봐야 우리가 정한 값 그대로 나오고, 화면에 실제로 칠해진 색은 알 방법이 없다.
(`prefers-color-scheme` 은 "사용자가 어두운 테마를 좋아한다" 는 뜻이지 "브라우저가 지금 색을
덧칠하고 있다" 는 뜻이 아니다. 우리는 이미 어두운 화면이라 그 값은 늘 dark 다.)

그래서 자동으로 되돌릴 수는 없고, **사람이 켜는 스위치**를 뒀다.

**설정 > 게임 > 화면 밝기 보정** — 켜면 채도와 밝기를 올려(`saturate(1.4) brightness(1.22)`)
덧씌워진 만큼을 되민다. 필요 없는 사람에게는 과해지므로 기본은 꺼둔다. 근본 해결(브라우저
다크 모드 끄기, 앱으로 설치하기)은 도움말에 그대로 남겼다.

필터는 `html` 이 아니라 `#root` 에 건다. `html` 에 걸면 배경이 필터 밖에 남아 화면
가장자리만 색이 달라진다.

## 곁다리로 드러난 것 — 설정이 화면끼리 공유되지 않았다

밝기 보정을 켰는데 아무 일도 일어나지 않았다. 원인은 보정 코드가 아니라 **설정 훅**이었다.

`usePreferences` 는 첫 렌더에서 한 번 읽고 끝이었다. 화면마다 자기 사본을 들고 있었으니
설정에서 바꿔도 다른 화면은 몰랐다. 밝기 보정을 보는 곳은 최상위 껍데기라 다시 그려질 일이
없어 **영영 반영되지 않았다.**

같은 이유로 이전부터 조용히 어긋나던 것이 있었다 — 설정에서 소리를 꺼도 게임 화면 구석의
음소거 버튼은 켜진 모습 그대로였다(새로고침해야 맞춰졌다).

이제 설정이 바뀌면 보고 있는 모든 화면이 함께 따라간다. 한 곳에서 바꾸면 모두 같은 값을
보여야 "같은 설정" 이라고 할 수 있다.

## 증상

게임에 들어가 **대기 화면에서 화면이 확대**됐다.

## 짚어본 것들

먼저 대기 화면이 가로로 넘치는지 재봤다. 넘치면 브라우저가 화면에 맞추려고 배율을
건드린다. 360×740 에서 문서 폭과 화면 폭이 모두 360 이라 **넘침은 없었다.**

전체화면(`useImmersiveGame`)도 의심했지만 그것은 게임 화면에만 걸려 있고 대기 화면에는
없다.

남은 것은 두 가지였고, 둘 다 막았다.

## 1. 더블탭 확대

`index.html` 의 뷰포트에 `user-scalable=no` 를 넣어두었는데, **그것만으로는 부족하다.**
삼성 인터넷과 iOS 사파리에는 접근성을 이유로 그 지시를 무시하는 설정이 있고, 그 상태에서는
버튼을 연달아 누르는 것이 더블탭으로 읽혀 화면이 통째로 확대된다. 대기 화면에서 준비
버튼을 두 번 누르다 그렇게 되기 쉽다.

```css
touch-action: manipulation;
```

이 한 줄은 **밀기와 손가락 두 개로 하는 확대는 그대로 두고 더블탭 확대만** 막는다.
눈이 불편한 사람이 일부러 확대하는 길은 남겨두는 것이 맞다 — `user-scalable=no` 를 더
세게 밀어붙이는 방향으로 가지 않은 이유다.

## 2. 브라우저의 글자 키우기

안드로이드는 화면에 비해 글이 작다고 판단하면 글자만 슬쩍 키운다(font boosting).
그러면 글자와 아이콘·버튼의 크기가 어긋나 **화면이 확대된 것처럼 보인다.** 우리는 크기를
다 정해두었으므로 손대지 말라고 못박았다.

```css
-webkit-text-size-adjust: 100%;
text-size-adjust: 100%;
```

## 어제 반만 막았다

어제 `touch-action: manipulation` 으로 **더블탭 확대**를 막으면서, 손가락 두 개로 벌리는
확대는 일부러 남겨두었다. 눈이 불편한 사람이 일부러 확대하는 길은 있어야 한다고 봤다.

그런데 실제로 써보니 그쪽이 더 문제였다. **카드를 쥐고 두는 게임이라 손가락이 화면에
계속 닿아 있다.** 한 번 확대되면 판이 어긋난 채로 남은 라운드를 두게 된다. 확대를 원해서
한 것이 아니라 카드를 집다가 그렇게 된 것이다.

## 두 곳을 막아야 한다

확대를 막는 방법이 브라우저마다 다르다.

| | 안드로이드 | iOS 사파리 |
| --- | --- | --- |
| `user-scalable=no` | 설정으로 무시할 수 있음 | 무시함 |
| `touch-action` | **먹힘** | 확대 제스처에는 안 먹힘 |
| `gesture*` 이벤트 | 없는 이벤트 | **먹힘** |

그래서 둘 다 걸었다.

```css
touch-action: pan-x pan-y;   /* none 으로 하면 스크롤까지 죽는다 */
```

```ts
for (const name of ['gesturestart', 'gesturechange', 'gestureend']) {
  document.addEventListener(name, (e) => e.preventDefault(), { passive: false });
}
```

`gesture*` 는 표준에 없는 사파리 전용 이벤트라 타입이 없다. 문자열로 붙였다.

## `*` 에 걸지 않은 이유

모든 요소에 걸면 확실해 보이지만 **슬라이더가 망가질 수 있다.** 프라이빗 방의 턴 시간
슬라이더는 가로로 끄는 조작인데, 거기까지 `pan-x` 를 걸면 브라우저가 그 손짓을 "화면을
옆으로 미는 것" 으로 가져갈 수 있다.

걸 필요도 없다. 확대가 되는지는 **손이 닿은 요소부터 위로 조상을 다 훑어 정해진다.**
`html`·`body`·`#root` 가 막고 있으면 그 안의 무엇을 짚어도 확대되지 않는다. 브라우저에서
실제 값을 읽어 확인했다 — 가운데 요소는 `auto` 인데도 조상이 막고 있어 확대가 안 된다.
