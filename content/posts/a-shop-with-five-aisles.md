---## 예전 구분이 왜 틀렸나

탭이 **카드 / 테이블 / 이모트 / 아바타 / 세트** 였다. 이것은 "게임 안 어디에 있는가" 를
따른 구분이라 파는 쪽의 사정이지 사는 쪽의 사정이 아니다. 카드 뒷면과 테이블은 **둘 다
나만 보는 것**이고 아바타는 **남에게 보이는 것**인데 같은 층위에 놓여 있었다.

## 새 구성

| 갈래 | 무엇을 바꾸나 | 누가 보나 |
| --- | --- | --- |
| **아바타** | 얼굴 동그라미 **안의 그림** | 같이 하는 사람들에게도 |
| **스킨** | 게임판과 배경 | 나에게만 |
| **이모티콘** | 게임 중 보내는 표정 | 같이 하는 사람들에게도 |
| **엠블럼** | 첫 화면 가운데 인물 사진 | 나에게만 |
| **내 보유** | 가진 것들 | — |

**"누가 보나" 를 목록 위와 미리보기 양쪽에 적었다.** 남에게 보이는지는 그림으로 표현할
방법이 없는데, 살지 말지를 정하는 데는 그것이 제일 크게 작용한다. 나만 보는 것에 돈을
쓰는 사람과 남에게 보이려고 쓰는 사람은 다른 물건을 산다.

## 아바타 — 색이 아니라 안의 내용을 바꾼다

`Avatar` 에 `image` 를 더했다. 지금까지는 색 위에 이름 첫 글자를 썼는데, 색만 바꾸면
여러 사람이 모였을 때 서로 구분은 되어도 **"내 것" 이라는 느낌이 안 든다.**

글자는 없애지 않고 그림이 없을 때의 기본값으로 남겼다. 그림이 없는 사람이 훨씬 많고,
그때 빈 동그라미가 뜨면 계정이 잘못된 것처럼 보인다.

첫 상품은 **이미 있는 카드 그림 넷**(제우스·헤라클레스·메두사·헤르메스)으로 냈다. 새로
그릴 것이 없어 오늘 바로 쓸 수 있고, 게임에서 이미 보던 얼굴이라 낯설지 않다.

## 이모티콘 — 이름과 소리

"이모트" 는 만드는 사람들의 말이다. 화면에서는 **이모티콘**으로 통일했다.

소리는 이미 나고 있었는데 **받는 사람에게만** 났다. 누른 사람 화면은 조용해서, 소리가
났는지 자기가 알 수가 없으니 두 번 세 번 누르게 된다. 누른 사람도 함께 듣게 고쳤다 —
이모티콘은 "봤지?" 하고 부르는 신호라 같은 방 전원이 같은 순간에 같은 소리를 들어야 한다.

## 엠블럼 — 자리를 하나만 둔다

인물 그림은 나중에 받기로 했다. 그때까지 **없는 상품을 있는 척 늘어놓지 않는다** —
눌러봤는데 살 수 없는 칸이 줄줄이 있으면 상점 전체가 준비 안 된 곳으로 보인다.
지금 쓰는 메두사 하나와 "준비 중" 자리 하나뿐이다.

## 내 보유 — 읽는 곳을 하나로 모았다

**아직 아무것도 살 수 없다.** 무엇을 샀는지 서버가 기억하는 자리가 없어서, 지금 결제를
열면 사과만 빠져나가고 산 것은 남지 않는다. 그래서 내 보유에는 기본 제공 넷이 들어간다.

그래도 읽는 곳은 `src/lib/ownership.ts` 하나로 모았다. 나중에 서버 보유 목록이 생기면
그 파일만 바꾸면 화면은 그대로다 — 전적이 기기/서버를 가르면서도 화면은 한 벌인 것과 같다.

**내 보유에서 눌러도 같은 미리보기가 열린다.** 산 것을 다시 볼 수 없으면 무엇을 갖고
있는지 잊는다.

## 확인

브라우저(390×844)로 다섯 탭과 미리보기를 모두 열어 봤다. 아바타 그림이 동그라미 안에
제대로 들어가고, 내 보유에 기본 제공 넷이 뜨는 것을 확인했다.

## 다음

**고른 것을 실제로 입히는 일**은 다음이다. 아바타와 이모티콘은 남에게 보이므로 계정에
저장해야 하고(서버 열 추가), 그 전에 보유 목록이 서버에 있어야 한다. 순서가 있다.
스킨과 엠블럼은 나만 보는 것이라 이 기기에만 저장하면 되므로 먼저 붙일 수 있다.

## 무엇을 잘못했나

어제 이모티콘을 16종으로 늘리면서 **열여섯 개를 전부 기본 제공으로 돌렸다.** 이유는 이랬다:
지금 이 게임은 결제 흐름이 없어서 아무것도 살 수 없으니, 열둘에 값을 매기면 상점에는 값표가
붙는데 살 방법이 없고 게임에서도 못 쓴다 — 만들어 놓고 아무도 못 쓰는 물건이 열둘 생긴다.

이 판단이 틀렸다. "이모티콘 다 보유중으로 하면 어떡해? 기본 4개만 주고 나머지는 팔아야지."

**결제 기능이 아직 없다는 것은 무료로 풀 이유가 되지 않는다.** 상점의 가격 구조는 이 게임의
수익 설계 그 자체다. 그리고 한 번 준 것은 나중에 다시 유료로 되돌릴 수 없다 — 이미 갖고
있던 사람에게서 뺏는 꼴이 되기 때문이다. 결제가 붙기 전까지 유료 이모티콘이 안 쓰이는
상태로 남는 것은 감수할 일이지, 값표를 지워서 해결할 일이 아니었다.

## 되돌린 것

기본 넷(웃음·화남·당황·고민)만 무료로 남기고 나머지 열둘은 100 사과짜리 상품으로 되돌렸다.
어제 떼어낸 `pending` 은 그대로 둔다 — 그림이 생긴 것은 사실이라 "준비 중" 은 아니다.

바탕색은 열여섯 칸 모두 `--surface-2` 로 통일한 채 뒀다. 예전 유료분에는 진한 아바타 색이
깔려 있었는데, 그 위에 얹히는 것이 **색이 있는 선 그림**이라 어두운 바탕에서는 선이 묻힌다.
무료와 유료는 바탕색이 아니라 등급표와 값으로 갈린다.

## 게임 화면은 가진 것만 보여준다

값을 매겨두고 게임에서는 전부 누를 수 있으면 파는 의미가 없다. `ownership.ts` 에
`ownedEmotes()` 를 두고, 이모트 격자가 이 목록으로만 그리게 했다.

```ts
const usable = useMemo(() => {
  const mine = new Set(ownedEmotes());
  return EMOTES.filter((def) => mine.has(def.kind));
}, []);
```

한 번만 읽는다. 보유 목록은 상점에서만 바뀌는데 상점은 다른 화면이라, 돌아오면 이 컴포넌트가
다시 그려지면서 새로 읽는다. 판이 도는 중에 저장소를 계속 들여다볼 이유가 없다.

순서는 카탈로그 순서를 그대로 쓴다. 카탈로그가 `EMOTES` 순서를 따르므로, **열둘을 다 사도
격자는 처음 봤을 때와 같은 자리에 같은 것이 있다.** 사고 나서 자리가 흐트러지면 손이 헤맨다.

격자는 이제 산 만큼 자란다 — 무료 넷일 때는 한 줄, 다 모으면 네 줄이다. 4칸씩 접히는
격자라 몇 개를 갖고 있든 한 번에 다 보인다.

## 값표가 다시 사라지지 않도록

같은 실수를 코드가 막게 했다. `emotes.test.ts` 에 두 가지를 더했다.

- 무료는 정확히 넷(웃음·당황·고민·화남)뿐이고, 나머지는 값이 0보다 크다.
- 아무것도 안 샀으면 쓸 수 있는 이모트가 그 넷뿐이고, 사면 그 자리에 더해진다.

## 문서

- `docs/PRD.md` 5-1 과 가격표 — "전부 기본 제공" 을 "기본 4종 무료 + 12종 100 사과" 로.
- 기획 문서 — "16종" 옆에 기본 4종과 상점 12종의
  구분을 적었다. 게임위에 중요한 것은 여전히 "글자를 직접 입력할 수단이 없다" 는 쪽이다.

## 확인

이모트 테스트 12건과 `src/lib` 테스트 전부 통과(합 88건).

**전체 테스트는 이번에 돌리지 않았다.** 같은 저장소에서 다른 작업(약한 카드 보너스 되돌리기)이
동시에 진행 중이라 `src/game/constants.ts` 가 중간 상태였고, `trick.test.ts` 와 `Guide.tsx`
가 없어진 `BONUS_LUCKY_SEVEN` 을 아직 부르고 있었다. **이 커밋에는 그쪽 파일을 담지 않았다** —
경로를 하나씩 지정해 이모티콘 관련 파일만 올렸다.
