---## 왜 지금

> "움직이는 엠블럼 나한테 선물해줘"

선물하려니 **넣을 자리가 없었다.** 무엇을 샀는지는 그때까지 브라우저의 localStorage 뿐이었고,
그래서 상점에 값이 적혀 있어도 **실제로는 아무것도 살 수 없었다** — `ownership.ts` 머리말에
그렇게 적혀 있었다. 폰을 바꾸면 사라지고, 개발자 도구를 열 줄 알면 얼마든지 만들어낼 수도
있었다.

주소에 `?gift=...` 를 붙여 받아지게 하는 임시 고리를 만들려다 **접었다.** 지금은 보유가 기기
안에서만 뜻이 있어 괜찮지만, 사과로 진짜 결제를 여는 순간 **그 링크가 그대로 구멍**이 된다.

그래서 제대로 만들었다. 이건 어차피 **상점 전체를 막고 있던 부분**이다.

## 만든 것

### 표 — `owned_items`

```sql
PRIMARY KEY (user_id, item_id)
```

한 사람이 같은 것을 두 번 갖지 못하는 것을 **표 자체가 막는다.** 코드에서 "이미 있나" 를 본
뒤 넣으면 두 번 눌렀을 때 사이를 비집고 둘 다 들어갈 수 있다.

`source` 로 `purchase`(사과를 내고 산 것)와 `gift`(운영자가 준 것)를 갈라 적는다. 유료 재화가
얽히면 **"왜 이 사람이 이걸 갖고 있지"** 를 반드시 묻게 된다.

### 값은 서버가 정한다

사는 쪽은 **무엇을 살지(id)만** 보낸다. 값을 함께 보내면 그 값을 서버가 믿어야 하고, 그러면
1 사과로 600짜리를 산다.

그런데 서버는 카탈로그(`shopCatalog.ts`)를 읽을 수 없다 — 그림을 가져오는 파일이라 워커에서
풀 방법이 없다. 그래서 값만 담은 `server/src/prices.ts` 를 따로 뒀다. **두 군데에 적힌 숫자는
언젠가 어긋나므로** 사람이 기억할 일로 두지 않고 테스트가 잡는다
(`src/lib/__tests__/prices.test.ts`, 4건).

- 값이 있는 상품을 서버가 모르면 → 운다
- 값이 서로 다르면 → 운다
- 카탈로그에서 사라진 상품이 서버에 남아 있으면 → 운다
- 기본 제공인데 값이 붙어 있으면 → 운다

**모르는 id 는 거절한다.** 값을 모르는 것을 파느니 못 파는 편이 안전하다.

### 사는 순서

**이미 가졌는지 → 값 치르기 → 넣기.** 값부터 치르면 이미 가진 것을 또 사서 사과만 잃는다.

### 화면

- 보유 목록은 **기기 것과 서버 것을 합친다.** 기기 것은 기본 제공이라 로그인 전에도 화면이
  비지 않고, 서버 것은 계정에 붙어 폰을 바꿔도 따라온다
- "구매는 준비 중입니다" 를 지우고 **진짜로 산다.** 사고 나면 보유 목록과 잔액을 둘 다 다시 읽는다
- 두 번 눌러 두 번 사는 것을 막았다(`buying`)
- 화면의 잔액 검사는 **미리 알려주려는 것**이지 막는 장치가 아니다. 진짜 판단은 서버가 한다

## 확인

- 인증 없이 `/api/owned` → `401`, `/api/owned/buy` → `401`, `GET` 으로 구매 → `401`
- `tsc --noEmit`(클라이언트·서버), `vitest run` **349건**(값 대조 4건 추가), `vite build` 통과
- 마이그레이션은 **`0010` 만 파일로 적용했다.** `migrations apply` 를 쓰면 0007 의
  `UPDATE users SET apples = apples / 10` 이 다시 돌아 모두의 사과가 10분의 1이 된다

- 서버: `schoolking-room` 버전 `(배포 id)`
- 클라이언트: `main` 푸시로 Cloudflare Pages 자동 배포

## 남은 것

- **선물은 아직 못 넣었다.** 계정이 열둘인데 어느 것이 본인인지 확인이 필요하다.
  `grantItem()` 이 준비돼 있으므로 닉네임만 알면 한 줄이다
- 산 것을 **되돌리는 길이 없다.** 잘못 샀을 때의 환불은 아직 없다. 유료 결제가 붙기 전에 정해야 한다

## 선물 완료 (2026-09-05)

`A 님` 계정에 `emblem-mirror-motion` 을 `source='gift'` 로 넣었다.

닉네임이 같은 계정이 둘이라 **활동 내역으로 갈랐다** — `255d52f1…` 은 사과 20개에 적립 내역
20건(마지막 2026-09-04), `55a9968b…` 는 사과 0에 내역 0건이었다. 사람이 쓰는 계정은 앞의
것이다. 남의 계정에 쓰는 일은 되돌리기 어려우므로 **닉네임만 보고 넣지 않았다.**

상점 화면에서 값 대신 **"보유 중"** 과 체크 표시가 뜨는 것까지 확인했다.

뒤의 조건이 핵심이었다. **"다른 사람에게도 보여야 해"** — 그래서 이건 선물 한 줄이 아니라
기능 하나였다.

## 왜 한 줄로 안 되나

`equipped.ts` 에 이미 이유가 적혀 있었다.

> 아바타와 이모티콘은 다르다. 그 둘은 같이 하는 사람들 화면에 뜨므로 계정에 저장해야 하고,
> 그래서 서버 작업이 끝난 뒤에 붙는다.

지금까지 **아바타는 입을 수가 없었다.** 상점에 팔고는 있었지만 갈아입기가 스킨과 엠블럼에만
있었다. 그 둘은 나에게만 보이니 기기에 둬도 되지만, 아바타를 기기에 두면 **남의 화면에는
영원히 기본 아바타**로 보인다. 내 폰에서만 바뀌는 것은 바꾼 것이 아니다.

## 만든 것

### `equipped_items` 표 — 갈래마다 하나

기본키가 `(user_id, kind)` 다. 가진 것은 여럿이지만 입는 것은 갈래마다 하나이므로, 갈아입으면
줄이 늘지 않고 그 줄이 바뀐다(UPSERT). **표가 그것을 보장한다.**

스킨과 엠블럼은 여기 오지 않는다. 남에게 안 보이므로 기기에 두는 편이 낫다 — 로그인 없이도
고를 수 있다.

### 무엇을 입을 수 있는지는 서버가 판단한다

남에게 보이는 것이라 **안 산 캐릭터를 입고 나타나면 파는 의미가 없다.** 화면도 같은 것을
확인하지만 그것은 미리 알려주려는 것이고, 진짜 판단은 `server/src/equipped.ts` 가 한다.

**갈래를 몸통에서 받지 않고 id 에서 읽는다.** 보내는 쪽이 "이건 avatarChar 야" 라고 우기게
두면 배경 자리에 인물을 넣어 남의 화면을 망가뜨릴 수 있다.

서버에도 아바타 목록이 필요해졌다(`prices.ts` 의 `AVATAR_ITEMS`). `PRICES` 는 "살 수 있는 것"
이라 **기본 제공이 빠져 있는데**, 입는 쪽에서는 공짜인 것도 입을 수 있어야 하고 오히려
대부분이 그것을 입고 있다. 카탈로그와 어긋나는 것은 테스트 5건이 잡는다.

### 방이 계정을 알게 했다

여기가 제일 손이 많이 갔다. 방(`GameRoom`)은 **이름을 주소의 질의 문자열로 받고 있었다** —
즉 본인이 말한 것을 그대로 쓴다. 아바타를 같은 길로 보내면 누구나 아무 캐릭터나 입을 수 있다.

그래서 첫 메시지(`hello`)에 **토큰을 실었다.** 방이 토큰으로 누구인지 확인하고, 그 계정이
입고 있는 것을 D1 에서 읽는다. 주소가 아니라 **몸통에 싣는다** — 주소는 서버 기록과 중계
장비에 그대로 남는다.

방이 D1 을 보려면 `env` 가 필요해서 DO 생성자에 붙였다.

읽기에 실패해도 **판을 막지 않는다.** 아바타는 꾸미기고, 그것 때문에 게임을 못 하게 되는
편이 훨씬 나쁘다. 기본 얼굴로 앉을 뿐이다.

### 흐르는 길

```
계정(D1) → hello 토큰 확인 → Attachment → Member → Seat → Player.avatarChar → 모두의 화면
```

판 상태에는 **id 만** 싣는다. 그림을 실으면 상태가 통째로 무거워지고, 상품 그림을 고쳐도
이미 시작한 판에는 옛 그림이 남는다. 그림 찾기는 `src/lib/avatarArt.ts` 한 군데로 모았다 —
여러 화면에 흩어지면 언젠가 한 곳만 고쳐서 게임과 대기실의 얼굴이 달라진다.

자리를 비운 사람의 기록에도 함께 적는다. 준비하고 나간 사람은 판에 들어가는데, 그때 얼굴만
기본으로 돌아가면 안 된다.

### 보이는 곳

플레이어 띠 · 점수판 · 최종 순위 · 예측 화면 · 라운드 결과 · 대기실 명단 · 첫 화면 프로필.

`Avatar` 에 `background` 를 더했다. `color` 로는 상품 배경을 표현할 수 없다 — `color` 는
`--avatar-초록` 같은 토큰 **이름**이고, 상품 배경은 그라데이션까지 담은 완성된 CSS 값이다.

### 상점

아바타에도 **사용하기**가 생겼다. **먼저 화면을 바꾸지 않는다** — 서버가 거절할 수 있고,
그때 내 화면만 바뀌어 있으면 남들에게는 그대로인 채 나만 바뀐 줄 안다.

## 남은 것

- **이모티콘도 같은 길로 가야 한다.** 그것도 남에게 보이는데 아직 기기 저장소에 있다
  (`ownedEmotes`). 아바타를 뚫었으니 이제 같은 자리에 붙이면 된다
- 방이 아바타를 읽는 시점은 **접속할 때 한 번**이다. 게임 도중에 갈아입으면 그 판에는
  반영되지 않는다. 지금은 상점과 게임을 동시에 열 수 없으니 문제가 없다
