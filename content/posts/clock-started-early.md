---## 제보

> "아직도 가끔 선일 때 초가 10초에서 안 시작하고 더 낮게 시작할 때가 있어."

어제 고친 것(트릭 마지막 사람이 다음 선이면 시계가 아예 안 돌아가던 문제)과 **다른 버그**였다.

## 원인 — 붙잡아 보여주는 동안에도 시계가 돌았다

트릭이 끝나면 화면은 결과를 잠깐 붙잡아 보여준다.

- 보통 트릭 **2초** (`TRICK_HOLD_MS`)
- 메두사가 잘라낸 트릭 **3.4초** (`TRICK_HOLD_CUT_MS`)

그런데 그 사이 **엔진은 이미 다음 트릭을 열고 승자를 선으로 세워둔다.** 시계도 그 시점부터
돌기 시작한다. 그래서 선이 된 사람은 **화면이 정리되기도 전에 2~3.4초를 까먹은 채** 자기
차례를 맞는다. 10초가 아니라 8초, 메두사 판 뒤에는 6.6초에서 시작한 것이다.

**"가끔" 이었던 이유**도 여기 있다. 선이 아닌 사람은 앞사람들이 내는 동안 화면이 이미
정리되어 있어서 온전한 10초를 받는다. **트릭을 이겨 선이 된 사람만** 겪는다.

## 고친 방법 — 아무도 둘 수 없는 시간은 세지 않는다

양쪽을 같이 고쳤다. 한쪽만 고치면 화면과 실제 판정이 어긋난다.

**화면** (`GameScreen`) — 붙잡는 동안에는 시계를 멈춘다.

```ts
const clockRunning = Boolean(game && game.status === 'playing') && !holdingResult;
```

**서버** (`gameHost.deadlineFor`) — 붙잡는 시간만큼 마감을 뒤로 민다.

```ts
const hold = holdMsAfterTrick(state);
if (active.control === 'ai') return now + Math.max(hold, AI_THINK_MS);
return now + hold + state.config.turnSeconds * 1000;
```

봇 쪽은 **어제 넣었던 `justCut` 특례를 이 계산으로 흡수했다.** "잘라낸 트릭이면 더 기다린다"
가 사실은 "붙잡는 시간만큼 기다린다" 의 특수한 경우였다. 보통 트릭(2초)도 봇의 생각 시간
(1.2초)보다 길어서, 이제는 보통 트릭 뒤에도 봇이 화면을 기다린다.

## 확인

Playwright 로 연습 게임을 돌려 **내 차례가 시작되는 순간의 초를 여섯 번** 모았다.

```
내 차례 시작 초: 10, 10, 10, 10, 10, 10  → 전부 10초 ✅
```

`tsc --noEmit`(클라이언트·서버), `vitest run` 345건, `vite build` 통과.
`server/src/gameHost.ts` 가 바뀌었으므로 **서버 먼저** 배포했다.

- 서버: `schoolking-room` 버전 `(배포 id)`
- 클라이언트: `main` 푸시로 Cloudflare Pages 자동 배포
