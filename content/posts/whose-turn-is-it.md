---## 1. 트릭의 마지막 사람이 다음 선이면 시계가 안 돌아갔다

> "한 톤의 마지막 사람이 그다음 손이 되면 대기 시간 리셋이 안돼"

**진짜 버그였다.** `gameStore.applyState` 는 이 조건으로만 시계를 되돌렸다.

```ts
const turnChanged =
  prev === null ||
  prev.activePlayerId !== next.activePlayerId ||
  prev.round?.phase !== round?.phase ||
  prev.round?.number !== round?.number;
```

트릭의 **마지막 사람이 그 트릭을 이기면** 그 사람이 곧바로 다음 트릭의 선이 된다. 그러면
`activePlayerId` 가 그대로여서 **네 조건이 전부 거짓**이 되고, 방금 자기 차례에 쓰고 남은
시간으로 새 트릭을 시작하게 된다. 2초 남았으면 카드를 보기도 전에 시간초과가 난다.

**서버는 멀쩡했다.** `gameHost` 는 액션을 받을 때마다 `deadlineFor(next, now)` 로 마감을
새로 잰다. 어긋난 것은 **화면의 시계**와, 그 시계로 굴러가는 **연습 게임**이었다.

조건에 한 줄을 더했다 — **트릭이 끝난 것도 "차례가 바뀐 것"** 이다.

```ts
prev.round?.completedTricks.length !== round?.completedTricks.length
```

## 2. 내 차례면 판 테두리에 불이 들어온다

> "선한 사람이 자기가 선인지를 잘 몰라"

위쪽 아바타에 차례 표시(민트 링·맥동·삼각형)가 있는데도 놓친다. 이유가 분명하다 —
**카드를 고를 때 눈은 아래쪽 손패에 있다.** 화면 맨 위의 신호는 시야에 없다.

그래서 화면 한가운데인 **판(트릭 존) 테두리**에 같은 신호를 준다. 금색으로 숨 쉬듯 밝아졌다
어두워진다. 금색으로 고른 것은 왕관·승자 링과 같은 "지금 이 자리" 계열이라 새로 배울 것이
없기 때문이다.

## 3. 5초 남으면 흔들리고 진동한다

**내 차례이고 5초 이하**일 때만이다. 남의 차례에도 흔들면 판마다 화면이 흔들려 아무도 못
견딘다.

- **흔들림** — 작게(1~1.5px), 계속. 크게 한 번 흔들면 놀라기만 하고 "시간이 없다" 는 뜻이
  전달되지 않는다
- **진동** — `navigator.vibrate([120, 80, 120])` 를 **다급해지는 순간 한 번**. 화면 흔들림은
  보고 있어야 알지만 진동은 **폰을 내려놓고 있어도 온다.** 차례를 놓치는 것을 막는 것이
  목적이라 이쪽이 더 중요하다

`navigator.vibrate` 는 안드로이드 크롬에만 있다(iOS 사파리에는 없다). 없으면 조용히 넘어간다.
화면을 한 번도 만진 적이 없으면 브라우저가 막기도 해서 `try/catch` 로 감쌌다.

기준값은 `URGENT_SECONDS = 5` 로 `game/constants.ts` 에 두고 **`Timer` 의 기본값도 여기서**
가져오게 했다. 시계가 빨개지는 순간과 흔들리는 순간이 어긋나면 안 되기 때문이다.

### 움직임을 줄여달라고 한 기기에서는

흔들지 않는다. 대신 화면 가장자리를 붉게 물들여 "시간이 없다" 만 전한다. **진동은 그대로
온다** — 진동은 움직임이 아니라 알림이다.

## 확인

Playwright 로 연습 게임을 돌려 확인했다.

- 내 차례 판 테두리 불 — **켜짐** ✅ (금색 테두리 확인)
- 5초 이하에서 흔들림 클래스 — **붙음** ✅

`tsc --noEmit`, `vitest run` 343건, `vite build` 통과.
화면과 클라이언트 타이머만 바뀌어 **서버 배포는 없다** (`URGENT_SECONDS` 는 서버가 쓰지 않는다).

## 메모 — 커밋 체인이 두 번 끊겼다

`git pull --rebase && cat > devlog.md && git add -A && git commit` 처럼 이어 붙였는데,
**작업 트리에 변경이 남아 있으면 `git pull --rebase` 가 실패**해서 개발일지 작성이 통째로
건너뛰어졌다(커밋은 따로 돌아갔다). 앞으로는 **커밋을 먼저 하고 pull 은 push 직전에** 한다.
