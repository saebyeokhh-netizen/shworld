---## 무엇이 문제였나

초대 팝업은 이미 있었다. 그런데 **앱이 켜져 있을 때만** 떴다. 15초마다 서버에 "나 초대받은
거 있어?" 하고 물어보는 방식(`src/lib/presence.ts`)이라, 앱을 닫아두면 물어볼 사람이 없다.

친구를 부르는 쪽에서 보면 이렇다 — 방을 만들고 초대를 눌렀는데, 상대가 앱을 꺼두었으면
**아무 일도 일어나지 않는다.** 카톡으로 "게임 켜봐" 를 따로 보내야 한다.

## 웹 푸시를 붙였다

브라우저가 대신 알림을 받아 띄워주므로 앱이 꺼져 있어도 닿는다.

| | 전 | 후 |
|---|---|---|
| 앱이 켜져 있을 때 | 최대 15초 뒤 팝업 | **즉시** |
| 앱이 꺼져 있을 때 | 안 뜸 | **폰 알림** |
| 알림을 눌렀을 때 | — | 앱이 열리며 그 방으로 |

앱이 켜져 있을 때도 빨라진 이유는 아래 "두 번 뜨지 않게" 를 참고.

## 암호화를 직접 구현했다

웹 푸시는 **본문을 암호화해서 보내야 한다**(RFC 8291). 푸시 서비스(구글·애플 서버)를
거쳐 가는데 그들이 내용을 들여다볼 수 없어야 하기 때문이다. 보낸 우리도 못 읽는다 —
받는 기기만 푼다.

`web-push` 같은 npm 라이브러리를 쓸 수 없었다. **Node 의 crypto 를 쓰는데 Cloudflare
Workers 에는 그것이 없다.** 그래서 `crypto.subtle`(Web Crypto)만으로 다시 썼다
(`server/src/push.ts`).

- **RFC 8292 (VAPID)** — ES256 으로 JWT 를 서명해 "이 알림은 우리가 보낸 것" 을 증명한다.
  Web Crypto 가 주는 raw(r‖s, 64바이트) 서명을 그대로 쓴다. DER 로 바꾸면 안 된다
- **RFC 8291 (본문 암호화)** — 일회용 P-256 키쌍 → ECDH → HKDF-SHA256 → AES-128-GCM.
  머리 86바이트가 `salt(16) + 레코드 크기(4) + 키 길이(1) + 서버 공개키(65)` 로 정해져 있다

**테스트에서 실제로 복호화해 본다.** 구독자 쪽 키쌍을 테스트 안에서 만들어 반대편 계산을
직접 해보고 원문이 나오는지 확인한다(15건). 암호화 코드는 "돌아간다" 와 "맞다" 가 다르다 —
틀려도 예외가 안 나고 그냥 받는 쪽에서 조용히 버려지기 때문에, 왕복을 확인하지 않으면
배포하고 나서야 안 되는 것을 알게 된다.

## 두 번 뜨지 않게

앱을 보고 있는 중에 알림이 오면 **같은 초대가 두 번 보인다** — 폰 알림 하나, 앱 안 팝업
하나. 알림을 누르면 이미 열려 있는 화면을 또 연다.

그래서 서비스 워커가 먼저 **창이 보이는 중인지** 확인한다(`clients.matchAll`). 보이는
중이면 알림을 띄우지 않고 창에 "왔다" 고만 알린다. 창은 그 신호를 받아 폴링을 즉시 한 번
돌린다. **덕분에 앱이 켜져 있을 때도 최대 15초 기다리던 것이 즉시가 됐다.**

규격상 주의할 것이 하나 있다. 푸시를 받으면 **반드시 눈에 보이는 알림을 띄워야 한다**
(`userVisibleOnly`). 조용히 넘기는 것을 브라우저가 싫어해서, 반복하면 구독을 끊어버린다.
위처럼 창이 보이는 경우는 예외로 인정되는 범위이지만, 본문을 못 읽는 경우에까지 조용히
넘기지 않도록 일반 문구로라도 띄운다.

## 스위치는 거짓말을 하면 안 된다

설정의 알림 스위치는 **상태를 저장하지 않고 화면을 열 때마다 물어본다.** 저장해 두면
다른 기기나 브라우저 설정에서 끈 것을 모른 채 "켜짐" 으로 보여주게 된다.

그리고 **왜 안 되는지를 반드시 적는다.** 상태가 다섯이다.

| 상태 | 화면에 적는 말 |
|---|---|
| `unsupported` | 이 브라우저에서는 쓸 수 없어요. 아이폰이라면 홈 화면에 추가한 뒤 열어주세요 |
| `unavailable` | 알림 준비가 아직 안 됐어요 (서버에 키가 없는 배포) |
| `denied` | 브라우저 설정에서 허용해주세요 |
| `off` / `on` | — |

특히 **아이폰은 홈 화면에 추가한 경우에만** 웹 푸시가 온다(iOS 16.4+). 사파리 탭으로
열어두면 안 된다. 그 사실을 모르면 영원히 해결할 수 없으므로 화면에 적었다.

한 번 거부하면 앱에서 다시 물어볼 수 없다는 것도 중요하다. 그래서 **아무 때나 묻지 않고
사람이 스위치를 켤 때만** 묻는다.

## 초대 응답을 알림이 붙잡지 않게

푸시 발송은 남의 서버(푸시 서비스)에 HTTPS 요청을 보내는 일이라 얼마나 걸릴지 모른다.
그것을 기다리면 **방을 만든 사람이 "초대됨" 을 보기까지 그만큼 멈춰 있다.**

`ctx.waitUntil()` 로 응답을 먼저 돌려주고 뒤에서 마저 보낸다. 이걸 쓰려고 워커의
`fetch(request, env)` 에 `ctx` 를 받아 `handleApi` 까지 넘겼다.

`notifyInvite` 는 **절대 던지지 않는다.** 알림이 안 갔다고 초대 자체가 실패하면 안 된다 —
앱을 켜두었다면 폴링으로 어차피 뜬다.

## 테스트가 잡아준 것

탈퇴 코드에 `push_subscriptions` 를 빠뜨렸는데 기존 테스트가 잡았다.

```
AssertionError: deleteAccount 에서 빠진 표: push_subscriptions
```

`user_id` 를 가진 표를 전부 훑어 탈퇴 시 지워지는지 확인하는 테스트다. 남겨두면
**탈퇴한 사람의 폰으로 계속 알림이 갈 수 있다.** 이런 테스트가 새 표를 만들 때마다
값을 한다.

## 배포할 때 해야 할 것

코드만으로는 안 된다. 사람이 두 가지를 해줘야 한다.

```powershell
# 1. 표 만들기
npx wrangler d1 execute schoolking --remote --file=migrations/0012_push_subscriptions.sql

# 2. 개인키 넣기 (공개키와 연락처는 wrangler.jsonc 에 있다)
npx wrangler secret put VAPID_PRIVATE_KEY

# 3. 배포
npx wrangler deploy
```

개인키를 넣기 전까지 `/api/push/key` 는 `null` 을 돌려주고, 앱은 알림 스위치를 **아예
보여주지 않는다.** 켤 수 없는 스위치를 보여주는 것보다 낫다.

⚠️ **공개키를 바꾸면 이미 구독한 사람들의 알림이 전부 끊긴다.** 브라우저가 구독할 때 이
값을 함께 저장해 두기 때문이다. 바꿔야 한다면 표를 비우고 다시 켜달라고 해야 한다.
