---홈의 트로피는 "지금까지 딴 점수 합" 인데, 그것만으로는 **내가 잘하는 편인지 알 수가 없다.**
비교할 대상이 없기 때문이다. 그래서 한 주를 잘라 남과 견주는 화면을 붙였다.

## 무엇으로 줄을 세우나

**이번 주에 딴 점수의 합.** 홈의 트로피와 같은 계산을 한 주로 자른 것뿐이라 이용자가 따로
배울 규칙이 없다.

대신 **많이 한 사람이 유리하다** — 판수가 곧 점수다. 이건 숨길 게 아니라 보여줄 것이라
판단해서, 순위판에 판수를 함께 적었다. "저 사람은 40판 해서 1등이구나" 가 보이면 납득이
되지만, 감추면 "왜 저 사람이 1등이지" 가 된다.

동점일 때는 **판을 적게 하고 그만큼 딴 사람**을 위로 올린다. 그것마저 같으면 닉네임 순인데,
이 마지막 기준이 없으면 새로고침할 때마다 순서가 뒤바뀌어 버그로 보인다.

봇과 둔 판(`online = 0`)은 세지 않는다. 넣으면 순위판이 "누가 연습을 많이 했나" 가 된다.

## 주 경계 — 여기가 제일 조심스러웠다

**월요일 0시 한국시간**에 새로 시작한다. 서버(UTC) 기준으로 자르면 **월요일 아침 9시에
순위가 초기화된다.** 일요일 밤에 열심히 한 사람의 점수가 월요일 오전에 갑자기 사라진 것처럼
보인다.

`played_at` 이 ISO 문자열(UTC)로 저장돼 있어서, 주 시작을 같은 형식의 문자열로 만들어
`played_at >= ?` 한 줄로 자른다. ISO 문자열은 **사전순 비교가 곧 시간순 비교**라 날짜 함수가
필요 없다.

이 계산에 테스트를 일곱 개 붙였다. 쓰다가 하나가 실패했는데 **코드가 아니라 테스트가
틀렸다.** "UTC 로는 월요일인데 한국은 아직 일요일" 인 경우를 상정했는데, 한국시간은 UTC 보다
**앞서므로** 그런 경우는 없다. 어긋남은 한쪽으로만 생긴다. 그 사실을 주석으로 남겼다.

## 어디에 보이게 했나

**홈의 트로피 배지를 눌러서** 들어간다. 거기 이미 내 승점이 적혀 있으니 눌러서 남과 견주는
화면으로 이어지는 것이 자연스럽고, 바로 옆 사과 배지도 눌러서 여는 방식이라 손이 같은 곳을
찾는다.

**홈 아래 버튼 줄은 늘리지 않았다.** 지금 넷(스킨상점·전적·친구·출석체크)인데 다섯이 되면
좁은 폰에서 눌리는 자리가 너무 작아진다.

전적 화면의 요약 아래에도 길을 하나 냈다. 전적을 보러 온 사람이 궁금한 건 결국 "그래서 내가
잘하는 편인가" 인데, 내 숫자만으로는 답이 안 되기 때문이다.

## 로그인 없이 볼 수 있다

순위는 누구의 것도 아닌 공개된 기록이고, 처음 온 사람이 **"여기 사람이 있구나" 를 보고 계정을
만들지 정하는 자리**이기도 하다. 로그인부터 요구하면 그 판단을 못 하게 막는 셈이다.

로그인해서 보면 내 줄에 테두리가 붙고, 50위 밖이면 목록 끝에 내 자리를 따로 붙인다 —
스크롤로 찾게 두지 않는다.

## 확인

`tsc --noEmit` 통과(앱·서버), 테스트 **283개**(새로 13개) 통과.

SQL 은 로컬 D1 에 시험 데이터를 넣고 직접 돌려 확인했다.

| 넣은 것 | 기대 | 결과 |
|---|---|---|
| 50점 1판 / 50점 2판 | 동점이면 판수 적은 쪽이 위 | ✅ 1위·2위 |
| 30점 3판 | 그 아래 | ✅ 3위 |
| 지난 주 999점 | 안 세임 | ✅ 안 나옴 |
| 봇과 둔 999점 | 안 세임 | ✅ 안 나옴 |
| 내 순위 계산 | 목록 순서와 같아야 함 | ✅ 1·2·3위로 일치 |

내 순위를 목록과 **같은 기준으로** 세는지가 특히 중요하다. 동점 규칙을 빼먹으면 목록에서는
7위인데 아래 내 줄에는 5위라고 적히는 일이 생긴다.

브라우저로도 열어봤다. 순위 세 줄이 제대로 그려지고, 홈의 트로피 배지가 순위판으로 이어지고,
콘솔 오류가 없다.

## ⚠️ 서버를 따로 올려야 한다

새 API(`/api/ranking/weekly`)와 인덱스(`0008_ranking.sql`)는 **방 서버 쪽이라 push 만으로는
올라가지 않는다.**

```bash
cd server
npx wrangler d1 migrations apply schoolking --remote
npx wrangler deploy
```

올리기 전까지 화면은 "순위를 불러오지 못했어요" 로 뜬다. 흰 화면이 되거나 앱이 죽지는 않게
해뒀지만, 두 배포 사이의 틈은 짧을수록 좋다.

## 앞으로 볼 것

지금 이용자가 거의 없어서 순위판에 두세 명만 뜬다. 사람이 모이기 전에는 오히려 썰렁해 보일 수
있으니, **친구끼리 순위**를 먼저 여는 것도 방법이다. 데이터는 이미 다 있어서 질의에 친구
조건 하나만 더하면 된다.

## 왜 레벨을 뺐나

레벨과 순위는 둘 다 "얼마나 잘하나" 를 말하지만 성질이 다르다.

| | 레벨 | 순위 |
| --- | --- | --- |
| 견주는 대상 | 과거의 나 | 이번 주의 남 |
| 방향 | 오르기만 함 | 오르내림 |
| 초기화 | 없음 | 매주 월요일 |
| 필요한 것 | 내 기록만 | 서버 + 다른 사람 |

레벨은 한 번 오르면 내려가지 않는다. 안정감은 있지만 **이번 주에 잘했는지를 말해주지
못한다.** 반년을 쉬어도 Lv.6 이고, 그 숫자는 오늘 한 판을 할 이유가 되지 않는다.

순위는 매주 새로 시작한다. 지난주에 밀렸어도 월요일이면 다시 자리가 있고, 옆의 트로피
배지를 누르면 가는 순위판과 같은 숫자라 두 곳이 서로를 설명한다.

## 새 API 는 없다

`GET /api/ranking/weekly` 가 이미 `me: RankingEntry | null` 을 함께 돌려준다. 순위판
화면이 "내 자리" 를 아래에 붙이려고 쓰던 값을 홈에서도 그대로 읽는다. 서버는 한 줄도
바뀌지 않았고, 순위 계산이 두 군데로 갈릴 일도 없다.

## 세 가지 상태를 구분한다

```
null    읽는 중 / 서버가 답을 안 줌   →  "—"
"none"  로그인은 했는데 이번 주 판이 없음 →  "순위 없음"
숫자     이번 주 내 등수              →  "12위"
```

"읽는 중" 과 "순위 없음" 을 뭉뚱그리면, 서버가 잠깐 흔들렸을 뿐인데 이번 주 성적이
날아간 것처럼 보인다. 못 읽었을 때는 모른다고(`—`) 말하지, 없다고 단정하지 않는다.
로그인 전에는 물어볼 것도 없어 예전처럼 "전적 저장" 이 그대로 뜬다.

`me` 는 이번 주에 한 판이라도 했을 때만 온다(`server/src/ranking.ts` 의 `myRank`).
그래서 오래 쉬었다 온 사람은 "순위 없음" 을 보고, 한 판 하면 바로 숫자가 생긴다.

## 지운 것

`src/lib/level.ts` 와 그 테스트 12개를 지웠다. 쓰는 곳이 없어졌고, 안 쓰는 규칙을
남겨두면 다음 사람이 "레벨도 어딘가 뜨는구나" 하고 착각한다. 곡선이 다시 필요하면
커밋 f1d1384 에 그대로 있다.

---

## 두 순위는 다른 일을 한다

어제 만든 순위판은 **주간**이다. 오늘 아침 홈 프로필 아래 자리를 레벨에서 순위로
바꾸면서 그 주간 값을 그대로 끌어다 썼는데, 그 자리에는 맞지 않는다.

| | 순위판 (주간) | 프로필 아래 (전체 기간) |
| --- | --- | --- |
| 기간 | 이번 주 | 계정 만든 뒤 전부 |
| 초기화 | 매주 월요일 0시(KST) | 없음 |
| 하는 일 | 이번 주에 한 판 할 이유 | "내가 여기서 몇 등인가" |

주간은 매주 새로 시작해야 밀린 사람에게도 자리가 생긴다. 반대로 프로필에 박히는 숫자는
쉽게 사라지지 않아야 "내 자리" 로 읽힌다. 월요일마다 프로필이 `순위 없음` 으로 비면
오래 한 사람일수록 손해 본 기분이 든다.

## 질의는 한 벌 그대로다

기간을 자르는 건 `WHERE ... AND m.played_at >= ?` 한 줄뿐이었다. 그래서 전체 기간은
질의를 새로 쓰는 게 아니라 **아무것도 걸리지 않는 시각**을 넣는 것으로 끝난다.

```ts
export const ALL_TIME_SINCE = '1970-01-01T00:00:00.000Z';
```

질의를 두 벌로 늘리면 동점 규칙(점수 → 판수 적은 순 → 닉네임)이나 봇 제외(`online = 1`)
가 한쪽에만 반영되는 사고가 언젠가 난다. `topOfWeek` 과 `myRank` 는 손대지 않았다.

빈 문자열도 사전순으로는 통하지만 로그에 찍혔을 때 "기간을 안 넣었나" 로 읽혀서 실제
날짜를 썼다. 이 상수가 정말 모든 기록보다 앞서는지는 테스트로 박아뒀다 — 아니면 옛날
판이 조용히 순위에서 빠진다.

## 목록은 안 보낸다

`GET /api/ranking/me` 를 따로 뒀다. 주간 순위판(`/api/ranking/weekly`)은 상위 50명
목록과 내 자리를 함께 주는데, 홈은 열릴 때마다 순위를 물어보면서 그 50줄을 쓰지 않는다.

로그인이 필요하다(401). 남의 순위가 아니라 내 순위라서다.

## 표시

```
숫자     지금까지의 내 등수          →  "12위"
"none"  사람과 둔 판이 아직 없음     →  "순위 없음"
null    읽는 중 / 서버 무응답        →  "—"
```

`순위 없음` 은 봇하고만 둔 사람에게도 뜬다. 순위는 사람과 둔 판(`online = 1`)만 세기
때문이다. 홈의 트로피 숫자는 봇과 둔 판까지 더한 값이라 둘이 어긋나 보일 수 있는데,
봇 상대로는 얼마든지 이길 수 있어서 순위에 넣으면 "누가 연습을 많이 했나" 가 된다.

## 배포

서버(워커)를 새로 올려야 `/api/ranking/me` 가 생긴다. 올리기 전에는 홈이 404 를 받고
`—` 를 보여준다 — 화면이 깨지지는 않는다.
