---## 오늘 한 일

병렬 에이전트들이 만들어 놓은 조각을 하나로 합쳐, **로그인부터 라운드 정산까지 한 판이 실제로 도는 상태**까지 갔다. 커밋 두 개(`868a177` 규칙 엔진·AI·스토어, `aa10695` 화면 전체)로 정리됐고 타입체크·테스트·빌드 모두 클린이다.

- 비게임 화면 8종: 스플래시 · 로그인 · 튜토리얼 · 홈 · 로비 · 프라이빗 방 · 코인샵 · 스킨샵
- 플레이 화면: `GameScreen` 이 `PlayerStrip` / `TrickZone` / `HandRail` / `BidOverlay` / `RoundResultOverlay` / `EmoteBar` 를 조립하고 스토어에 연결
- 검증: `vitest` 140개 통과, `tsc --noEmit` 에러 0, `vite build` 성공(100 모듈)

## 세션이 둘 겹쳤다 — 그리고 어떻게 정리했나

사용량 한도로 세션이 끊겼다가 재개하면서 **같은 저장소를 두 Claude 세션이 동시에 작업하는 상황**이 생겼다. 이전 세션의 백그라운드 에이전트가 아직 살아 있었고, 새 세션에서도 같은 범위로 에이전트를 띄웠기 때문이다.

증상은 `src/screens/game/` 에 같은 역할의 컴포넌트가 두 벌 생긴 것이었다.

| 역할 | 이전 세션 | 새 세션 |
|---|---|---|
| 손패 | `HandRail` | `Hand` |
| 입찰 팝업 | `BidOverlay` | `BidPanel` |
| 결과 팝업 | `RoundResultOverlay` | `ResultOverlay` |

두 세션이 서로 메시지를 주고받아 경계를 정했다. 이전 세션은 추가 쓰기를 멈추고, 통합과 커밋은 새 세션이 전담했다.

**어느 쪽을 남길지는 코드 품질이 아니라 목업으로 판정했다.** 양쪽 다 잘 짜여 있었지만 목업과 맞는 쪽은 하나뿐이었다.

- `mock_play-1.png` 의 손패는 부채꼴이 아니라 **골드 테두리 레일 안 일렬 배치**이고, 위에 "내 예상 2승 · 지금 1승" 라벨, 아래에 별도 **"카드 내기" 버튼**이 있다. 즉 탭 즉시 제출이 아니라 **선택 → 확정 2단계**다. `HandRail` 이 이 구조였다.
- `mock_bid-1.png` 는 상단에 다른 참가자의 **"확정 ✓ / 고민중"** 상태 줄이 있다. `BidOverlay` 에만 있었다.

그래서 `HandRail` / `BidOverlay` / `RoundResultOverlay` 를 남기고 나머지 한 벌은 지웠다. `GameScreen` 배선도 그쪽 props 계약에 맞춰 다시 썼다.

교훈은 두 가지다. 하나는 **백그라운드 에이전트는 세션이 끊겨도 살아 있을 수 있다**는 것. 재개할 때는 새로 띄우기 전에 이미 도는 작업이 있는지부터 확인해야 한다. 다른 하나는 **중복이 생겼을 때 판정 기준을 코드가 아니라 기획 산출물(목업/PRD)에 두면 논쟁이 없다**는 것이다.

## 실패하던 테스트 3건은 엔진 버그가 아니었다

`engine.test.ts` 가 3건 깨져 있었는데 원인은 전부 테스트 쪽이었다.

- 두 건은 선도자를 `p1` 으로 고정 가정했다. 실제 규칙은 `firstLeaderIndex = (roundNumber - 1) % playerCount` 로 **라운드마다 한 자리씩 돈다.** 3인 게임 3라운드의 선도자는 `p3` 다.
- 한 건은 `expect(...).toBe(s === s ? nextRound(s) : s)` 처럼 항상 참이라 아무것도 검증하지 못하는 단언이었다. 대기 상태 / 입찰 중 / 카드 대결 중 세 경우를 각각 확인하도록 바꿨다.

## 통합하면서 정한 것

**`GameScreen` 만 스토어를 안다.** 나머지 플레이 화면 컴포넌트는 props 로 받고 콜백으로 돌려주는 프레젠테이션 컴포넌트로 유지했다. Playroom 멀티플레이로 옮길 때 갈아끼울 지점을 한 곳으로 모으기 위해서다.

**규칙은 화면에서 다시 구현하지 않는다.** "지금 낼 수 있는 카드"가 필요하면 스토어에 필드를 늘리는 대신 `@/game` 의 `getPlayableCards(myHand, currentTrick)` 를 화면에서 호출해 파생시켰다.

**트릭 결과 홀드(1.4초).** 엔진은 트릭이 끝나는 즉시 다음 트릭을 연다. 그러면 승자 골드 링을 볼 틈이 없다. 엔진이나 스토어에 연출용 상태를 넣지 않고, 새 트릭에 첫 카드가 깔리기 전까지 방금 끝난 트릭을 대신 보여주는 방식으로 화면에서만 처리했다.

**임시 진입 설정.** 로비가 아직 방 설정을 넘기지 않기 때문에 `/game` 으로 바로 들어오면 4인 · 15초 · 표준 특수카드 · 5라운드로 한 판을 시작한다. 덱 기준 자동 계산이면 16라운드까지 가서 체험용으로 잘랐다. 매칭이 붙으면 사라질 상수라 주석을 달아뒀다.

**상점은 화면까지만.** 코인 패키지와 스킨 가격은 PRD 6절 표를 상수 배열로 옮겼고, 구매 버튼은 "준비 중"이다. 재화·상품 테이블이 Supabase 로 들어오면 그 상수만 교체하면 된다. 세트 할인율은 계산하지 않고 PRD 표기값을 그대로 적었다 — 항목마다 반올림 기준이 달라 PRD 를 진실로 삼는 편이 맞다고 봤다.

**`RoomOptions` 계약.** 로비 → 프라이빗 방으로 넘기는 설정은 `PrivateRoom.tsx` 가 export 하고 `navigate(roomPath(code), { state })` 로 전달한다. URL 로 직접 들어와 state 가 없으면 기본값으로 되돌린다. `GameConfig` 의 부분집합이라 나중에 `mode` 만 붙이면 엔진 설정으로 그대로 넘어간다.

## 추가 — 브라우저 검증에서 앱이 아예 안 떴다

타입체크·테스트·빌드가 전부 통과한 상태에서 Playwright 로 실제 브라우저를 띄웠더니 **모든 경로가 흰 화면**이었다. 콘솔에는 `Cannot access 'ROUTES' before initialization` 만 계속 찍혔다.

원인은 순환 참조였다. `router.tsx` 가 모든 화면을 import 하고, 화면들은 다시 `router.tsx` 의 `ROUTES` 를 import 했다. 그런데 `Home.tsx` 는 `ROUTES.skinShop` 을 **모듈 최상위 상수 배열 안에서** 읽는다. 모듈 평가 순서상 `router.tsx` 본문이 실행되기 전에 `Home.tsx` 가 먼저 평가되므로, `const ROUTES` 는 아직 초기화 전(TDZ)이라 그 자리에서 터진다. 그리고 그게 앱 진입점이라 화면 하나가 아니라 전부가 죽는다.

**이 부류는 정적 검사로 안 걸린다.** 타입은 맞고, 번들도 정상적으로 만들어진다. 순환 참조 자체는 ESM 에서 합법이고, 실제로 터질지 여부는 "순환 안에서 값을 언제 읽느냐"에 달려 있다. 화면이 `ROUTES` 를 함수 본문(렌더 시점)에서만 읽었다면 아무 일도 없었을 것이다. `Home.tsx` 한 곳이 모듈 최상위에서 읽었을 뿐인데 앱 전체가 흰 화면이 됐다.

고친 방식은 순환을 끊는 것이다. 경로 상수를 **화면을 import 하지 않는** `src/routes.ts` 로 옮기고, 화면들은 `@/routes` 에서 가져가게 했다. `router.tsx` 는 재export 만 남겨 기존 import 도 깨지지 않게 했다. 규칙으로 적으면 이렇다 — **화면을 모아 라우팅 테이블을 만드는 파일과, 화면이 참조하는 상수를 두는 파일은 분리한다.**

같이 잡은 것 하나. 싱글 플레이에서 상대 전원에게 "AI 대체" 배지가 붙고 있었다. 로컬 게임의 봇은 `control: 'ai'` 로 시작하는데 화면이 그것만 보고 배지를 붙였기 때문이다. 하지만 "AI 대체"는 PRD 4절의 **AFK 로 사람이 대체됐다**는 뜻이라 의미가 다르고, 전원에게 붙으면 정작 사람이 이탈했을 때 그 사실이 묻힌다. `Player` 에 `isBot` 을 추가해 처음부터 봇인 경우와 구분했다. `consecutiveTimeouts` 로 판별하는 방법도 있었지만, 엔진이 정상 액션마다 그 값을 0 으로 되돌리기 때문에 대체된 뒤 AI 가 한 번만 두면 표시가 사라진다.

검증 결과는 이렇다. 화면 8종 렌더 확인, 실제 플레이 3라운드(예측 확정 → 카드 선택 → "카드 내기" → 트릭 판정 → 라운드 정산 → 다음 라운드) 통과, 점수판 오버레이 확인, **콘솔 에러 0건**.

교훈: **타입체크·테스트·빌드가 다 초록이어도 "화면이 뜬다"는 보장은 없다.** 화면 작업을 합친 뒤에는 브라우저를 한 번 띄워보는 단계가 따로 있어야 한다.
