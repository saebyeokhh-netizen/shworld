---## 증상

홈 화면에서 **트로피가 0**인데 그 옆의 **순위는 2위**로 떴다. 순위가 있다는 것은 사람과
둔 판이 있다는 뜻이니, 둘이 서로 모순이다.

## 원인 — 확인할 방법이 없는 채로 막혀 있었다

어제 만 14세 확인을 넣으면서 서버에 문을 달았다.

```ts
if (!user.ageChecked) return json(request, { error: AGE_REQUIRED }, 403);
```

그리고 화면 쪽은 **9월 2일부터** 생년월일을 묻도록 날짜로 잠갔다. 처리방침 새 판의
시행일에 맞추기 위해서였다.

두 결정이 각각은 맞았는데 **함께 놓으니 틀렸다.**

| | 지금 상태 |
|---|---|
| 화면 | 생년월일을 묻지 않음 (9/2부터) |
| 서버 | 확인 안 된 계정을 막음 (지금부터) |

그래서 **확인할 방법이 없는 채로 막혀 있었다.** 모든 계정의 `age_checked_at` 이 NULL 이니
전원이 해당된다.

그 결과가 이렇게 흘렀다.

```
GET /api/matches  →  403
      ↓
클라이언트: 응답이 실패면 빈 목록 (serverRecords.ts)
      ↓
summarize([])  →  totalScore: 0
      ↓
트로피 0
```

순위는 `/api/ranking/me` 라 이 문을 지나지 않아 멀쩡히 2위로 떴다. 두 숫자가 어긋나
보인 것이 오히려 단서였다.

## 더 큰 문제 — 새 판이 저장되지 않고 있었다

`/api/matches` 는 GET(읽기)과 POST(쓰기)를 함께 받는데, 문을 **메서드를 가르기 전에**
달아 두 가지가 모두 막혔다. 즉 어제 배포 이후로 **끝낸 판이 전적에 하나도 안 남고 있었다.**
화면에는 오류가 안 뜨므로(저장 실패를 조용히 넘긴다) 눈치채기 어려웠다.

## 고친 것 두 가지

**1. 서버도 같은 날짜를 본다.** 화면과 서버가 같은 `ageCheckStarted()` 를 쓴다. 9월 2일
전에는 서버도 막지 않는다.

```ts
function needsAgeCheck(user) {
  return ageCheckStarted() && !user.ageChecked;
}
```

**2. 쓰는 것만 막는다.** 막는 목적은 확인 전에 개인정보가 **쌓이는** 것을 멈추는 데 있다.
이미 있는 자기 기록을 읽는 것까지 막으면 얻는 것 없이 화면만 망가진다.

## 남는 교훈

**화면과 서버에 같은 규칙을 걸 때는 켜지는 시점도 같아야 한다.** 이 프로젝트는 화면이
자동 배포되고 서버는 손으로 올라가서 둘의 시점이 어긋나기 쉽다. 어제는 그 어긋남 때문에
로그인한 사람 전원이 확인 화면에 갇혔고, 오늘은 같은 어긋남이 반대 방향으로 났다.

날짜 잠금은 그 사고를 막으려고 넣은 장치인데, **한쪽에만 달아서 다시 같은 사고를 냈다.**
잠금은 규칙이 있는 모든 곳에 함께 달아야 한다.

## 증상

한 이용자가 온라인 게임을 마치자마자 회색 화면에 이런 글이 떴다.

```
Minified React error #130; visit https://react.dev/errors/130?args[]=undefined&args[]=
for the full message ...
```

React 130 은 **"컴포넌트로 그리려는 것이 undefined 다"** 라는 뜻이다.

## 원인 — 서버와 화면이 아는 보너스 종류가 달랐다

어제 보너스 규칙을 정리하면서 `luckySeven` 을 없앴다(a36ea5d). 화면 쪽 아이콘 표에서도
그 줄이 지워졌다.

```ts
const BONUS_ICON: Record<BonusType, ...> = {
  hakjuCapturesStudent: ZeusIcon,
  petrifyHakju: MedusaIcon,
  petrifyStudent: MedusaIcon,
  lowCardWin: TrophyIcon,
  // luckySeven 이 여기 있었다
};
```

그런데 **화면은 자동 배포, 서버는 손으로 배포**다. 화면은 곧바로 올라갔고 서버는 그대로
있었다. 옛 서버는 여전히 `luckySeven` 보너스를 계산해 보냈고, 새 화면은 그 이름을 모르니
`BONUS_ICON['luckySeven']` 이 `undefined` 가 됐다. 그것을 컴포넌트로 그리려는 순간
**앱 전체가 죽었다.**

라운드 결과 팝업이 보너스를 그리는 자리라, 하필 **판이 끝나는 순간**에 터졌다.

연습 게임에서는 안 나타난다. 연습은 규칙을 이 기기에서 돌리므로 새 코드끼리 맞기 때문이다.
**사람과 두는 판에서만** 났다.

## 두 가지를 고쳤다

**1. 서버를 올렸다.** 새 규칙이 올라갔으니 `luckySeven` 은 더 이상 만들어지지 않는다.

**2. 모르는 보너스는 건너뛰게 했다.** 이게 더 중요하다. 배포 시점이 어긋나는 것은 이
프로젝트의 **정상적인 한때의 상태**다(이번 주에만 세 번째다 — 연령 확인 때 두 번, 이번이
세 번째). 그때마다 앱이 통째로 죽으면 안 된다.

상 하나를 못 보여주는 것과 앱이 죽는 것은 비교할 일이 아니다.

## 같은 함정을 또 밟았다

이번 주에 같은 모양의 사고가 세 번 났다.

| | 화면 | 서버 |
| --- | --- | --- |
| 연령 확인 ① | 물어봄 | 모름 → 전원이 확인 화면에 갇힘 |
| 연령 확인 ② | 9/2부터 | 지금부터 차단 → 트로피 0, 전적 저장 안 됨 |
| 보너스 | 4종만 앎 | 5종 보냄 → **앱이 죽음** |

원인이 다 같다. **화면과 서버가 며칠씩 다른 상태로 돈다.** 그래서 규칙을 양쪽에 걸 때는
"둘이 어긋난 동안에도 화면이 살아 있는가" 를 먼저 물어야 한다.

특히 **서버가 보낸 문자열로 표를 찾는 곳**은 전부 위험하다. 표에 없으면 `undefined` 이고,
그것을 컴포넌트 자리에 두면 앱이 죽는다.
