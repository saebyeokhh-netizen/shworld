---멀티플레이 서버를 남의 서비스에서 우리 Cloudflare 계정으로 옮겼다.
**https://schoolking-room.shworld.workers.dev**

## 왜 옮겼나

Playroom 무료 플랜은 **하루 고유 사용자 10명**에서 막힌다. 그 위는 월 $10 다. 친구 몇 명과 테스트하는 동안은 괜찮지만, 링크를 조금만 넓게 뿌려도 11번째 사람부터 못 들어온다. 무료 범위에서 굴러가야 하는 프로젝트라 이 천장은 결국 문제가 된다.

계산해보니 Cloudflare Durable Objects 무료 한도가 훨씬 넉넉했다.

| 항목 | 무료 한도 | 우리 사용량 |
|---|---|---|
| 요청 | 하루 10만 | 한 판에 수백 건 |
| WebSocket 메시지 | **20건을 1건으로 계산** | 사실상 무시 가능 |
| 저장공간 | 5GB | 방 상태는 KB 단위 |
| 사용자 수 | **제한 없음** | — |

## 갈아끼우는 데 하루가 안 걸린 이유

Playroom 을 붙일 때 `RoomHandle` 이라는 인터페이스 뒤에 숨겨뒀다. 스토어와 화면은 "방" 이 무엇으로 구현됐는지 모른다. 그래서 이번 작업은 **어댑터 한 벌을 새로 쓰고 진입점에서 고르게 한 것**이 전부다. 게임 로직은 한 줄도 건드리지 않았고, 스토어 테스트(가짜 방을 끼워 도는)도 그대로 통과했다.

Playroom 어댑터는 지우지 않고 남겼다. `VITE_ROOM_TRANSPORT=playroom` 으로 되돌릴 수 있다.

## 서버가 하는 일

방 코드 하나당 Durable Object 인스턴스 하나가 생긴다. 같은 코드로 접속하면 어디서 접속하든 같은 인스턴스에 붙으므로, 방 목록이나 매칭 테이블 같은 게 필요 없다. 이게 Durable Objects 를 고른 이유다.

하는 일: 접속 관리, 참가자 명단, 호스트 지정과 승계, 메시지 전달, **손패를 주인에게만 보내기**.
하지 않는 일: 게임 규칙 판정. 지금은 여전히 호스트의 브라우저가 엔진을 돌린다.

## 옮기면서 이미 나아진 것 — 손패

Playroom 에서는 참가자 상태를 **방 전원이 읽을 수 있어서** 손패를 거기 실을 수 없었다. 호스트가 자기 메모리에 들고 있다가 RPC 로 요청받을 때만 주는 우회를 썼는데, 그 응답이 중계 과정에서 다른 클라이언트를 거치지 않는다는 보장은 문서에 없었다.

이제는 서버가 직접 나눠 보낸다. 호스트가 손패 전체를 서버에 올리면, 서버가 각 소켓에 그 사람 것만 골라 내려보낸다. **게스트 브라우저에는 남의 손패가 아예 도착하지 않는다.** 네트워크 탭을 열어도 없다.

호스트 본인이 다 아는 것은 여전하다. 그건 규칙 판정을 서버로 옮기는 2단계에서 해결된다.

## 헤맨 곳 — 하이버네이션과 인스턴스 변수

처음엔 접속 순서를 인스턴스 변수로 들고 "먼저 들어온 사람이 호스트" 로 정했다. 두 명이 들어갔는데 아무도 방장이 아니었다.

원인이 둘이었다.

1. `getWebSockets()` 의 배열 순서는 **접속 순서를 보장하지 않는다.**
2. WebSocket 하이버네이션을 쓰면 조용한 방은 메모리에서 내려간다. 무료 한도를 아끼는 핵심 기능인데, **다시 깨어날 때 인스턴스 변수가 사라진다.**

그래서 접속할 때 좌석 번호를 발급해 소켓에 붙이고(`serializeAttachment` 는 하이버네이션을 넘어 살아남는다), 발급기와 마지막 상태는 storage 에 넣었다. 호스트는 "붙어 있는 사람 중 좌석 번호가 가장 작은 사람" 으로 매번 계산한다. 호스트가 나가면 다음 사람이 자동으로 승계된다.

## 배포 주소를 환경변수로 두지 않은 이유

처음엔 `VITE_ROOM_SERVER_URL` 을 Cloudflare Pages 환경변수로 넣으려 했다. 그런데 이 값은 **비밀이 아니라 고정된 공개 주소**다. 환경변수로 두면 빌드 환경 어딘가에서 빠뜨렸을 때 프라이빗 방만 조용히 깨진다 — 나머지 화면은 멀쩡해서 한참 뒤에나 알게 되는 종류의 사고다.

그래서 코드에 기본값으로 적고, 환경변수는 "다른 서버로 붙여볼 때 덮어쓰는 값" 으로만 남겼다. 개발 중에는 로컬 wrangler 를 본다.

## 검증

`server/test/protocol-probe.cjs` — 브라우저 없이 소켓 두 개를 붙여 확인한다. 로컬과 배포본 양쪽에서 통과했다.

| 확인 | 결과 |
|---|---|
| 먼저 들어온 사람이 호스트 | OK |
| 게스트가 자기 손패를 받는다 | OK |
| **게스트에게 남의 손패가 가지 않는다** | OK |
| 게스트 액션이 호스트에게 전달된다 | OK |
| 게스트가 방 상태를 덮어쓸 수 없다 | OK |

배포본에서 브라우저 두 개로 실제 대국도 확인했다 — 입장, 방장/게스트 구분, 방장이 시작, 각자 자기 손패만 보고 각자 예측·카드 제출, 트릭 판정까지 동일. 콘솔 에러 0건.

연결 상대도 확인했다. `schoolking.pages.dev` 가 여는 소켓은 `wss://schoolking-room.shworld.workers.dev/room/...` 하나뿐이고, **외부 호스트로 나가는 요청은 없다.** Playroom 의존이 실제로 사라졌다.

## 다음 (2단계)

규칙 엔진을 서버로 옮긴다. 그러면 두 가지가 해결된다.

- 호스트 본인도 남의 손패를 모른다
- 호스트가 나가도 판이 이어진다

지금 만든 접속·명단·전달은 그대로 쓰고, `publish` 를 받는 자리에 엔진을 놓으면 된다. 엔진이 순수 함수라 파일을 그대로 옮겨 부르면 된다.

**시점은 "낯선 사람과 붙기 시작할 때"** — 빠른 매칭을 실제 온라인으로 열거나, 전적·랭킹처럼 점수가 기록으로 남는 기능을 붙이기 직전이다. 친구끼리 코드 공유해서 노는 지금 단계에서는 부정할 이유가 없다.

서버가 판을 돌리기 시작하니 알람 하나로 두 가지가 같이 풀렸다.

## 무엇이 바뀌었나

| | 전 | 후 |
|---|---|---|
| 카드를 나누는 곳 | 방장 브라우저 | **서버** |
| 승패·점수 판정 | 방장 브라우저 | **서버** |
| 봇의 수 | 방장 브라우저 | **서버** |
| 시간초과 판정 | 방장 폰의 시계 | **서버 시계** |
| 방장이 나가면 | 판이 멈춘다 | **판이 계속된다** |

클라이언트가 보내는 말도 바뀌었다. 예전에는 방장이 `publish` 로 **결과를 통보**했고
게스트는 `action` 을 방장에게 보냈다. 이제는 누구든 `intent`("이거 하겠다")만 보낸다.

**인텐트에는 playerId 를 싣지 않는다.** 보낸 사람이 곧 주인이고 그것은 서버만 안다 —
남의 이름으로 낼 방법이 아예 없어졌다.

## 옛 화면과 함께 살기

서버는 `publish` 와 `action` 을 **그대로 받아준다.** 단, 그 방에 서버가 돌리는 판이 이미
있으면 무시한다. 한 방에서 둘이 동시에 돌면 상태가 갈리기 때문이다.

덕분에 서버를 먼저 올려도 옛 화면은 그대로 돌아갔고, 화면만 롤백해도 정상으로 돌아온다.
옛 화면이 모두 사라지면 이 갈래는 지운다.

저장 키에도 형식 번호를 붙였다(`host:v1`). 예전 방식으로 저장된 방과 섞여 반쯤 읽힌 상태로
이상하게 도는 것보다, 없는 것으로 보고 새로 시작하는 편이 낫다.

## 마감 시각 하나로 시간을 다룬다

턴 제한시간, 봇이 생각하는 시간, 결과 화면 시간을 **하나의 마감 시각**으로 합쳤다.
Durable Object 가 알람을 하나만 걸면 되기 때문이다. 방이 조용하면 메모리에서 내려가므로,
알람이 아니면 아무도 깨워주지 않는다 — 방장이 앱을 꺼도 판이 사는 것은 이 알람 덕분이다.

## 확인한 것

**브라우저 둘로 실제 판을 돌렸다.**
- 방장이 시작 → 서버가 카드를 나눠 각자에게 **자기 손패만** 내려줬다
- 둘 다 예측 → 카드 단계로 넘어가고 서버가 준 남은 시간(19초)이 양쪽에 같이 떴다

**그리고 방장의 브라우저를 통째로 껐다.**
- +20초: 봇들이 예측을 냈다 (서버가 뒀다)
- +45초: 카드 단계로 넘어갔다
- +70초: 카드가 실제로 오갔고, 두 번 연속 시간초과한 자리에는 엔진 규칙대로 **AI 딱지**가
  붙었다

예전이라면 방장이 나가는 순간 멈췄을 판이다.

## 테스트

- `server/src/__tests__/gameHost.test.ts` (12개) — 규칙 자체
- `src/store/__tests__/onlineStore.test.ts` (10개) — **새 계약으로 다시 썼다.** 예전에는
  "호스트가 규칙을 적용하는지" 를 봤는데, 그 세계가 없어졌기 때문이다. 지금은 방장조차
  스스로 판을 열지 않고, 인텐트에 playerId 가 실리지 않으며, 온라인에서 봇도 시간초과도
  클라이언트가 건드리지 않는 것을 본다

전체 261개 통과.

## 남은 것 (5단계)

코인과 전적은 아직 **클라이언트가 "나 한 판 했다" 고 말하면** 기록된다. 판정이 서버로 왔으니
이제 서버가 직접 기록하게 만들 수 있다. 그러면 마지막 구멍이 닫힌다.
